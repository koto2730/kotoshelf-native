# kotoshelf

Fast, minimalist markdown note editor and personal knowledge base with Obsidian Tasks compatibility.

## 開発動機

Obsidianを便利に使っていて、便利だけどちょっと重いなと感じたので作ってみました。
Obsidianの保管庫だけでなく、リポジトリでの簡単なソース編集などにも使えるといいなと考えています。

サンプルは [`examples/`](examples/) にあります。ワークスペースのルートにコピーしてそのまま試せます。

## ワークスペース

`File → Open Folder…` で開いたフォルダがワークスペースです。コマンドラインからも開けます。

```bash
kotoshelf <フォルダ または ファイル>      # ファイルを渡すと、その親フォルダがワークスペースになる
kotoshelf --ssh <プロファイル名>           # 保存済みの SSH プロファイルで接続
```

ワークスペース内の設定は `.kotoshelf/` に保存されます（`settings.json`、`search.json`、保存前の履歴 `history/`）。
Git リポジトリでは、初回に `.kotoshelf/` を作成してよいか、`.gitignore` に追加するかを確認します。

## テンプレート

**ワークスペースのルート直下**の `Templates/` フォルダ（大文字小文字は問わない）の中にある、`template_` で始まるファイルがテンプレートです。
サブフォルダの中の `Templates/`（例: `notes/Templates/`）や、`Templates/` の下のさらに深い階層にあるファイルは無視されます。

```
Templates/template_daily.md      → 一覧では "daily"
Templates/template_reading.md    → 一覧では "reading"
```

挿入するには、挿入先のファイルを開き、`File → Insert Template…`（またはツールバーの `Template`）で選びます。
展開結果はカーソル位置に入ります。

### 展開される変数

| 記法 | 展開結果 |
| :--- | :--- |
| `{{today}}` / `{{yyyy-mm-dd}}` | 今日の日付（`2026-11-14`） |
| `{{yesterday}}` | 昨日の日付 |
| `{{tommorow}}` | 明日の日付（綴りは `tommorow` のみ。`tomorrow` は変数としては展開されない） |
| `{{today: n}}` / `{{today: -n}}` | 今日から n 日後 / n 日前（コロンのあとの空白は任意。例: `{{today: 7}}`） |
| `{{time}}` | 現在時刻（`HH:MM`、24 時間表記） |
| `{{yyyy}}` / `{{mm}}` / `{{dd}}` | 今日の年 / 月 / 日（互換用） |
| `{{task...}}` | 未完了タスクの一覧（[タスクリスト](#タスクリスト)を参照） |

未対応の `{{...}}` は、書いたとおりに残ります（入力ミスに気づけるように、あえて消しません）。

## インデックス（index.md）

ワークスペースを開くと、`Templates/template_index.md` があれば、そのテンプレートからワークスペース直下に `index.md` を作って開きます。

- ルート直下の `Templates/template_index.md` が **ない**場合は、`index.md` を作りません（何もしません）。`template_homepage.md` や、サブフォルダ内の `Templates/template_index.md` は無視されます。
- `index.md` の作成日または更新日が**今日**なら、上書きせずそのまま開きます。編集内容は消えません。
- 日付が変わった最初の起動では、テンプレートから作り直します。`{{today}}` や `{{task:...}}` が最新になります。
- 展開の仕様は通常のテンプレートと同じです（変数、`{{task}}` ともに使えます）。
- SSH ワークスペースでも同じ規則で動きます。リモートの `index.md` の更新日で判定します。

毎日の「今日やること」ページを自動で作る用途を想定しています。

## タスクリスト

Obsidian Tasks と同じ書式です。

```markdown
- [ ] 洗濯する ⏫ 📅 2026-11-14
- [ ] 水やり 🔁 every week on monday ⏳ 2026-11-17
```

| 記号 | 意味 | | 記号 | 意味 |
| :--- | :--- | --- | :--- | :--- |
| 📅 | 期日 | | 🔺 | 優先度 Highest |
| ⏳ | 予定日 | | ⏫ | 優先度 High |
| 🛫 | 開始日 | | 🔼 | 優先度 Medium |
| ➕ | 作成日 | | 🔽 | 優先度 Low |
| ✅ | 完了日（チェック時に自動で付く） | | ⏬ | 優先度 Lowest（記号なし = Normal） |
| ❌ | 中止日 | | 🔁 | 繰り返し |
| 🆔 | タスク ID | | 🏁 | 完了時の動作（`delete` で行ごと削除） |
| ⛔ | 依存先（🆔 の値を書く） | | | |

- チェックボックスは `- [ ]` / `* [ ]` / `+ [ ]` の直後に空白が必要です（`- [ ]月曜` のように詰めるとタスク扱いになりません）。
- コードフェンス（```` ``` ````）の中の行はタスクとして集計されません。集計対象は `.md` ファイルだけです。

### 入力補助

タスク行（タイトルを書いたあと）でスペースを押すと、優先度・日付・繰り返しなどを選ぶポップアップが開きます。
↑↓ で選び、Enter で挿入、Esc で閉じます。ほかの文字を入力すると、ポップアップは閉じてそのまま入力が続きます。

### 繰り返し（🔁）

`every [N] day(s) / week(s) / month(s) / year(s)` の形式です。

- `every weekday`（月〜金）、`every monday, friday`
- `every week on monday`、`every 2 weeks`
- `every month on the 15th`、`every month on the last day`、`every month on the 1st monday`
- 末尾に `when done` を付けると、完了した日を基準に次回を計算します。

繰り返しタスクをチェックすると、完了日が付き、次回分のタスクが作られます。

### `{{task}}` による一覧展開

テンプレート（`template_daily.md` や `template_index.md` など）に書くと、ワークスペース全体の未完了タスクを集めて展開します。

| 記法 | 説明 |
| :--- | :--- |
| `{{task:priority(today)}}` | 期日（📅）または予定日（⏳）が**今日以前**のタスクを優先度別に展開 |
| `{{task:priority(2026-10-16)}}` | 期日または予定日が**指定日以前**のタスクを優先度別に展開 |
| `{{task:priority(today+1)}}` | **明日以前**（`today-1`、`yesterday`、`tommorow` も使用可） |
| `{{task:high(today)}}` | 今日以前のうち **High** のみ（`highest`、`medium`、`low`、`lowest`、`none` も指定可） |
| `{{task(today)}}` | 今日以前の全タスク（優先度の見出しなし） |
| `{{task:priority}}` | 日付を問わず、全未完了タスクを優先度別に展開 |
| `{{task}}` | 日付を問わず、全未完了タスクを展開 |

`{{task:priority:today}}` のようにコロン区切りでも、`{{task:priority({{today}})}}` のように日付変数を入れ子にしても動きます。

### 双方向同期

展開されたタスク行の末尾には、元ファイルへのリンク（例: `[[notes/todo.md#Section]]`）が付きます。
エディタでもプレビューでも、そのチェックボックスをクリックすると、**元のノートのタスクも完了**します（完了日の記録、繰り返しの次回生成を含む）。
チェックを外すと、元のノート側も未完了に戻ります。

## 検索と絞り込み

左ペインの `Files` / `Search` で切り替えます（`Ctrl+Shift+F` で検索を開く）。

- **Files**: ファイルツリーです。右クリックで New File / New Folder / Rename / Duplicate / Delete（ゴミ箱へ）/ Open Terminal Here などが使えます。`Refresh`（F5）で再読み込みします。ツリー自体に絞り込み欄はありません。ファイルを探すときは Search を使います。
- **Search**: ワークスペース全体の全文検索と一括置換です。
  - スペース区切りの語は **AND** 検索です。`rust async` は、両方の語を含むファイルがヒットします。
  - `Regex` をオンにすると、入力全体を 1 つの正規表現として扱います。
  - `Case`（大文字小文字を区別）、`Include Ignored`（除外設定のファイルも対象にする）があります。
  - 画像・PDF・zip などは既定で検索対象外です。変えるには `.kotoshelf/search.json` の `exclude` に glob を書きます（例: `{"exclude": ["**/*.png", "drafts/**"]}`）。
  - 結果の行をクリックすると、そのファイルを開いて該当箇所を選択します。
  - `Replace All` で、結果全体を一括置換します。
- **Filter in results…**: 検索結果をその場で絞り込みます。再検索は不要です。スペース区切りの語は AND で、ファイルパスまたは該当行のプレビューに一致するものだけを残します。
- **📄 New Tab**: 絞り込み後の結果を、`[[ファイル名]]` リンク付きの Markdown として新しいタブに出力します。

## タブを並べる

複数のタブを横に並べて同時に編集できます。

1. 並べたいタブを `Ctrl+クリック`（個別）または `Shift+クリック`（範囲）で選びます。選んだタブには `☑` が付きます。
2. 次のいずれかで並べます。
   - `View → ◫ タブを並べる (選択した N 個)`
   - `View → ◫ すべてのタブを並べる`
   - タブを右クリック → `◫ アクティブタブと並べる` / `◫ 開いているタブをすべて並べる`
3. 並んでいるタブには `[1]` `[2]` の番号が付きます。
4. 並んでいる状態で別のタブを右クリックすると、`並べて表示にこのタブを追加` できます。並んでいるタブを右クリックして `並べて表示からこのタブを外す` ことも可能です。
5. 解除は `View → ✕ 並べて表示を解除`（またはタブの右クリックメニュー）です。ファイルは閉じません。

## API 送信（Send）

編集中のテキストを HTTP API に送り、返ってきた結果をノートに取り込みます。

### 設定

`Send → Settings…` を開きます。

- **Presets**: 送信先ごとの設定です。URL、メソッド、ヘッダー、ボディのテンプレート、レスポンスの取り込み方を決めます。
- **Tokens**: API キーなどの秘密情報です。`{{tokens.名前}}` で参照できます。値はマスク表示され、設定ファイルには書かれず OS の資格情報ストアに保存されます。

プリセットは `~/.kotoshelf/config.json` に保存されます。サンプルは [`examples/api-preset.example.json`](examples/api-preset.example.json) です。

### 使い方

1. 送りたい範囲を選択します（選択がなければ、ノート全体を送ります）。
2. `Send → Send Palette…`（`Ctrl+;`）を開き、↑↓ と Enter、または番号キーでプリセットを選びます。
3. 送信中は右下に `Sending…` が出ます。`Cancel (Esc)` で取り消せます。

### テンプレート変数（URL・ヘッダー・ボディ・プロンプト）

| 変数 | 内容 |
| :--- | :--- |
| `{{selection}}` | 選択範囲（なければノート全体）。プロンプトテンプレートがあれば、その展開結果を先頭に付けます |
| `{{selectionJson}}` | `selection` を JSON 文字列用にエスケープしたもの（外側の引用符は付かない） |
| `{{filename}}` | ファイル名（拡張子なし） |
| `{{tokens.NAME}}` | Tokens に登録した値。未登録なら `{{tokens.NAME}}` のまま残る |
| `{{sessionId}}` / `{{sessionIdJson}}` | 直前の応答の `SessionID: xxx` 行から取った値。なければ空文字 / `null` |

### レスポンスの扱い

- `Response JSON path`: 返ってきた JSON から値を取り出すパスです（例: `choices.0.message.content`、配列は数字で指定）。取り出せないときは、ボディ全体を使います。
- `Response target`:
  - `newTab`: 新しいタブに出力
  - `afterSelection`: 選択範囲の直後（なければカーソル位置）に挿入
  - `statusOnly`: ステータスバーに表示するだけ
- HTTP ステータスが 2xx 以外のときは、`response target` に関係なく、レスポンスのボディを新しいタブに出して失敗として知らせます。
- `Session ID path` / `Session updated path`: 応答から取り出した値を `SessionID: ...` の行として本文に追記します。次回の送信で `{{sessionId}}` として使えます。
- `Timeout`: 秒数です。`0` で無制限になります。
- URL は `http://` または `https://` のみ受け付けます。

API 送信はワークスペースの種類（ローカル / SSH）に関係なく、このアプリから直接送信先に接続します。

## SSH ワークスペース

リモートのフォルダを、ローカルと同じように開きます。必要なのは、手元の `ssh` コマンドと、パスワードなしで入れる設定（公開鍵認証 または ssh-agent）だけです。リモート側に何かをインストールする必要はありません。

### 接続

`File → Open Remote Workspace…` で、次を入力して `Connect` します。`Save` でプロファイルとして保存できます。

| 項目 | 説明 |
| :--- | :--- |
| Name | プロファイル名（`kotoshelf --ssh <Name>` で使う） |
| Host | ホスト名、または `~/.ssh/config` の Host 別名 |
| Port / User / Identity file | 任意。空なら `~/.ssh/config` の設定に従います |
| Remote folder | 開くリモートのフォルダ（絶対パス・必須）。空だと接続できません。`/` を指定するとサーバー全体が見えるため警告が出ますが、接続はできます |

- `ssh` コマンドの場所を変えたいときは、ダイアログで指定します（空なら PATH の `ssh`）。
- 認証は `BatchMode` です。パスワード入力のプロンプトには対応していません。
- 初めてのホストの鍵は自動で信頼し、**変更された鍵は拒否**します。
- 接続は `ControlMaster` で使い回し、通信に失敗すると、1 回だけ作り直して再試行します。

### できること / できないこと

- ツリー表示、ファイルの編集と保存、New File / Folder、Rename、Duplicate、ゴミ箱への移動（リモートの `.kotoshelf/.trash/` へ退避）、ワークスペース検索と置換、テンプレートと `index.md`、タスク一覧（`{{task}}`）、`Open SSH Terminal`（ローカルのターミナルで ssh を開く）に対応します。
- 保存前の履歴（`.kotoshelf/history`）は取りません。保存のたびに通信が増えるためです。
- 画像のプレビューは、20 MB までです。
- `.git`、`.kotoshelf`、`node_modules`、`target`、ドットで始まるフォルダは、ツリーと検索の対象外です。

## 主なショートカット

| キー | 動作 |
| :--- | :--- |
| `Ctrl+N` / `Ctrl+S` / `Ctrl+W` / `Ctrl+Q` | 新規 / 保存 / タブを閉じる / 終了 |

| `Ctrl+Enter` | カーソル行のタスクのチェックを切替 |

| `Ctrl+Plus` / `Ctrl+Minus` / `Ctrl+0` | 画面全体の拡大 / 縮小 / 戻す |
